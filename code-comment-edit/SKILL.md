## 書式

- ハードラップはしない
- プログラミング言語の標準として定められているフォーマットが存在する場合は、その書式を使用する

## 体裁

- 関数・変数・型などの要素に対するコメントは、<要素名> は～, <要素名> is ～のような書き出しはしない。直下の要素を指すことが明らかなため

## コメント内容

### 共通

文章は以下のルールに従わねばならない。

- 科学学術論文やデータシートのように、性質を端的に記述する
  - 性質の説明は、網羅的に行う
- 性質を説明する時に、具体例を列挙した例示や、その要素の外の具体的なふるまいを関連付けた説明は、特別に必要な時を除いて行わない
  - 記述の簡潔性を維持する意図と、その要素が知るべき知識的な境界を実装だけでなくコメントでも遵守する意図

### 通常のコード

以下を含める。

- その関数の役割を一言で表すもの
- その関数の振る舞いとそのパターン (一言で表した役割、引数、戻り値などから自明な場合は省略する)
- その要素の設計意図 (自明な場合は省略する)
- 引数の説明
- 戻り値の説明、例外の説明 (例外機構を使用する場合のみ)

### テストコード

以下を含める。

- テストの方法
- テストが期待する結果
- その仕様の役割と意図 (自明な場合は省略する)
